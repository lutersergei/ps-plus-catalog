# Бесконечная лента и буквенный индекс вместо пагинации

Дата: 2026-07-05. Статус: одобрено (ревью спеки пропущено по решению пользователя).

## Цель

Заменить номерную пагинацию каталога двумя механизмами: автоподгрузкой карточек
при скролле (бесконечная лента) и индексом быстрого перехода — по первой букве
названия при сортировке по названию, по шкале значений при других сортировках.

## Решения (зафиксированы в брейнсторме)

1. Номерная пагинация (1 2 3 …) удаляется полностью.
2. Основной способ листать — бесконечная подгрузка; быстрый переход — индекс.
3. Индекс зависит от сортировки: буквы A–Z для `title`; каждый год для `year`;
   пороги 100/90/…/0 для `critic`/`player`; пороги 0/5/10/20/40/60+ ч для
   `hltbmain`. Пустые бакеты не показываются.
4. Клик по бакету: если целевая карточка уже в DOM — плавный скролл к ней;
   иначе лента **перестраивается** с позиции бакета и грузится дальше вниз.
   Двунаправленной догрузки (заполнение промежутка при скролле вверх) НЕТ —
   осознанное упрощение; «назад» — повторный клик по индексу.
5. Fallback без JS: внизу ленты обычная ссылка «Показать ещё» (`?offset=N`),
   работающая как постраничная навигация. С JS она же — сторожевой элемент
   подгрузки и ручной retry при ошибке сети.
6. Позиция синхронизируется в URL (`history.replaceState`, параметр `offset`),
   чтобы перезагрузка и шаринг открывали то же место.
7. Два этапа: **этап 1** — лента (все сортировки) + буквенный индекс для
   `title`; **этап 2** — шкалы значений для остальных сортировок. При прочих
   сортировках на этапе 1 индекс просто не показывается.
8. Сортировка по названию переводится на `COLLATE NOCASE` (заодно чинит баг:
   «a Space for the Unbound» и др. нижнерегистровые названия сейчас уезжают в
   конец списка из-за байтового сравнения).
9. Названия не на A–Z попадают в бакет «#» в начале индекса.
10. Игры с NULL в сортируемом поле (хвост списка) индексом не покрываются.
11. Вместо «страница N из M» — живой счётчик «показано X из Y игр».

## Серверная часть

### Параметр offset

`offset` (число строк, кратно ничему — любое ≥0) принимается наравне с `page`;
при обоих заданных приоритет у `offset`. Внутри превращается в page/pageSize
эквивалент: выборка `LIMIT pageSize OFFSET offset`. Нормализация: отрицательные
→ 0, больше Total → клампится (отдаётся последняя партия).

### Фрагмент

`GET /?fragment=cards&offset=N&…фильтры…` рендерит ТОЛЬКО карточки — тот же
`{{block "cards"}}` шаблона, что использует полная страница (нулевое
дублирование вёрстки). Ответ дополняется заголовком `X-Total: <int>` (общее
число игр по фильтрам). Ошибочные значения fragment игнорируются (отдаётся
полная страница).

### Буквенные бакеты (этап 1)

Один SQL-запрос с теми же WHERE, что и основная выборка:

```sql
SELECT UPPER(SUBSTR(title,1,1)) AS letter, COUNT(*)
FROM games <where> GROUP BY letter ORDER BY letter COLLATE NOCASE
```

В Go буквы вне A–Z агрегируются в «#» (первым), затем счётчики превращаются в
кумулятивные смещения: offset(буквы) = сумма счётчиков всех предыдущих бакетов.
Результат — `[]LetterBucket{Letter string; Offset int}` в pageData. Считается
только при `sort=title` (в обоих направлениях `order`; при `desc` порядок
бакетов разворачивается).

### Изменение сортировки

В `sortColumns` колонка `title` получает `COLLATE NOCASE` в ORDER BY (и в
секондари-сортировке `title ASC` тоже). Белый список колонок сохраняется.

### Этап 2 (описание, реализация позже)

Аналогичные бакеты для других сортировок: годы — `GROUP BY release_year`;
оценки — `GROUP BY (score/10)*10` по соответствующей колонке средней; время —
кастомные пороги 0/5/10/20/40/60+ через CASE. Рендер тем же компонентом
индекса, подпись чипа = значение порога.

## Клиент (ванильный JS в том же inline-скрипте шаблона)

- Каждая карточка получает `data-i` — глобальный порядковый номер в выборке
  (сервер отдаёт и в полной странице, и во фрагменте).
- **Подгрузка**: `IntersectionObserver` на ссылке «Показать ещё». Появилась в
  вьюпорте → `fetch` фрагмента со следующим offset → вставка карточек в
  `.grid` → обновление счётчика (из `X-Total`), `href` ссылки и URL
  (`replaceState`). Получено меньше pageSize карточек → ссылка удаляется.
  Флаг in-flight защищает от параллельных запросов.
- **Прыжок по букве**: у чипа `data-offset`. Есть карточка с
  `data-i == offset` в DOM → `scrollIntoView({behavior:'smooth'})`. Нет →
  `grid.innerHTML = ''`, фетч фрагмента с этим offset, лента продолжается
  вниз оттуда. URL обновляется.
- **Подсветка активной буквы**: `IntersectionObserver` по карточкам; активен
  бакет последней карточки, пересёкшей верх вьюпорта. Дешёвая версия:
  обработчик на scroll с троттлингом, вычисление по `data-i` первой видимой
  карточки — допустимо, выбрать при реализации по простоте.
- **Ошибки сети**: фрагмент не загрузился → ссылка «Показать ещё» остаётся
  видимой и кликабельной (ручной retry). Никаких тостов.
- Уважать `prefers-reduced-motion`: вместо smooth-скролла — мгновенный.

## Раскладка индекса

Десктоп: вертикальная липкая рейка чипов справа от сетки (сетка сужается на
ширину рейки). Мобильный (<1200px): горизонтальная прокручиваемая строка чипов
между фильтрами и сеткой. Стиль чипов — как теги/пейджер текущего дизайна
(моно, скруглённые, кобальтовая подсветка активного).

## Тесты (этап 1)

- `offset` эквивалентен `page` (48 ≡ page 3 при pageSize 24); приоритет offset.
- Фрагмент отдаёт только карточки (нет `<head>`, нет формы), `X-Total` верен.
- Буквенные оффсеты: с фильтром и без; буква с нижнерегистровым названием
  считается в тот же бакет (NOCASE); «#»-бакет для не-букв.
- ORDER BY title NOCASE: «a Space for the Unbound» между соседями по алфавиту,
  а не в конце.
- Индекс рендерится при `sort=title` и НЕ рендерится при `sort=player`.
- Полная страница содержит ссылку «Показать ещё» с корректным offset и не
  содержит номерной пагинации.

## Вне объёма

- Двунаправленная догрузка промежутков.
- Виртуализация DOM (при 469 играх весь список в DOM допустим).
- Сохранение позиции скролла при возврате со страницы игры (полагаемся на
  bfcache браузера).
